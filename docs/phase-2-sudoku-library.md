# Phase 2 · SudokuPad-style solving and verified puzzle downloads

**Player outcome.** Open a Logic Masters Deutschland entry, see the setter’s instructions, solve the correct grid inside Sodukromental when supported, and reopen the same attempt offline. A player who wants the setter’s online player can reach it in one tap. These are proposed expansion requirements. The two reproduced failures below used the unmodified debug-era importer and store on repository `29c8940`. The exact puzzle in the tester’s report is unknown.

## Identifying Sven’s player

The product is **Sven Neumann’s SudokuPad**. Authors link puzzles to its web player, Cracking the Cryptic uses it, and Sven also publishes a separate Android companion. A setter explicitly labels the link on *All the Same and Never 4*. Use the documented and observable **web solving workflow** as the behavioral reference for our native Flutter player. Keep Sodukromental’s Library, author attribution, visual system and protected local progress. F-Puzzles is a separate creation/player format that SudokuPad can also import. [Developer’s site](https://svencodes.com/) · [Web player and controls](https://sudokupad.app/) · [Setter’s example](https://logic-masters.de/Raetselportal/Raetsel/zeigen.php?chlang=en&id=000HKK) · [Separate Android listing](https://play.google.com/store/apps/details?id=com.svencodes.sudokupad)

### What the puzzle details screen should say

| Action | Destination and outcome |
| --- | --- |
| **Play offline** / **Resume puzzle** | The verified native package and attempt on this device. Available only after the correct playable assets are committed. |
| **Open in SudokuPad web player** or **Open in F-Puzzles** | The exact selected author player URL, including appropriate puzzle-specific presentation options. Offer this online action even when the native representation is unsupported. If the author explicitly offers two editions, label both. |
| **View saved diagram** | The legible, locally saved author diagram **and** original instructions. Show why native play is unavailable. |
| **Read setter’s page** | The canonical Logic Masters entry with original rules, authorship, comments and solution-code workflow. The current **Open original** already intentionally goes here. Give it this unambiguous label. |
| **Watch CtC solve** | The verified, specific YouTube solve. Show a different-grid advisory for a known presentation change. Keep the badge, filter, newest-featured-first sorting and video link usable as metadata offline. Video playback requires connectivity. |

Keep the existing settings preference **Automatically download Logic Masters puzzles** off by default. A manual **Save for offline** attempts playable content first and reports the actual result, e.g. “Diagram saved. This 10×10 has repeating digits. Open in SudokuPad to play.” When no playable package or complete diagram can be saved, say **Online only** or **Retry download**, as appropriate, and retain the setter page. Listing metadata, author text alone, a player shell, a YouTube page or a successful HTTP status cannot mark a puzzle playable or diagram-saved. Show the number of *playable downloads* separately from diagrams when filtering Saved.

## Selecting and storing the correct board

1. **Collect candidates.** Keep the Logic Masters ID and canonical setter page. Extract author-body player candidates with anchor text, paragraph context, order and source language. Include a link wrapping the puzzle picture. Preserve secondary editions, the portal diagram, video evidence and portal links separately. Candidates from a cited earlier puzzle, series index or explanatory example have negative evidence. A first-listed anchor or a shared author is insufficient.
2. **Resolve the player link.** Direct recognized inline `scl`/`ctc` and `fpuz`/`fpuzzles` data can decode without another request. SudokuPad’s official loader also supports `scf` and extensions such as packs. Recognize these and report unsupported contents unless an implemented decoder passes fidelity tests. Resolve an approved short ID or namespaced slug such as `blobz/azul` through `https://sudokupad.app/api/puzzle/<id>`, encoding each segment and preserving the slash. Handle `/sudoku/` on `sudokupad.app` and `app.crackingthecryptic.com`, and `?puzzleid=` on the web player. The companion host `sudokupad.svencodes.com/puzzle/<id-or-package>` has its own route. Do not strip `/puzzle/` from the primary host, where the same path can serve a generic HTML shell. F-Puzzles `?load=` carries encoded data. Its `?id=<slug>` adapter resolves `https://tinyurl.com/<slug>` through the same bounded redirect policy. Preserve literal `+`, `/` and padding inside encoded payloads. Separate presentation settings from the lookup key. Retain them for the player and fidelity decision. Follow known author aliases such as TinyURL through a bounded chain (default five hops), require HTTPS and recognized alias/player hosts and route forms at each hop. Reject embedded credentials, nonstandard ports, loops and unexpected destinations from automatic resolution. Preserve the original user-openable link. A direct inline payload in the redirect location can be extracted before requesting player HTML. [SudokuPad loader](https://sudokupad.app/puzzleloader.js?v=0.616.0) · [Compact decoder](https://sudokupad.app/puzzlezipper.js?v=0.616.0) · [F-Puzzles URL handling](https://www.f-puzzles.com/Main.js?v=1.11.3) · [Namespaced example](https://sudokupad.app/blobz/azul)
3. **Establish identity.** Prefer the setter’s explicit current “play/solve” or title-labelled target corroborated by decoded title, author, stable key or an independently verified identical package. Preserve aliases and original titles for comparison. Allow localized, missing or deliberately different titles when other exact evidence exists. Reject a different puzzle explicitly identified in the paragraph or payload. Deduplicate equivalent keys/packages. Do not merge merely by title. If there are distinct author-sanctioned editions, present their labels. If ambiguity remains, show candidate choices with source context and leave automatic downloads unresolved. A verified CtC player can corroborate the exact author grid. A video, a title-only match or a modified broadcast grid cannot silently replace it.
4. **Validate bytes and capabilities.** A real SudokuPad API can return a valid `scl` string with a `text/html` MIME label. A player page can return actual HTML with the same label and status 200. Inspect bytes, decode a supported format as data, validate schema, playable cell mask, symbols, region and clue geometry, required assets and triggers. Recognize legacy compact objects and metadata stored in zero-cell cages. A successful decode alone grants no native play claim. Keep transport (`offline`, `retry`, `not found`), identity (`verified`, `multiple editions`, `ambiguous`), local capability and installed availability independently observable.
5. **Commit and repair.** Store portal revision, resolver version, source and resolved player URL, verified payload fingerprint, imported format, support report and local asset manifest. Download and verify into staging, then atomically expose the chosen revision. A changed redirect behind an unchanged title or URL must be detectable. Re-evaluate old first-anchor/alias records once after upgrade even when the portal revision is unchanged. For old records without a fingerprint, compare the cached player URL and normalized stored board (givens, regions, clue layers and supported rules) to the newly verified identity. When equivalence cannot be established, keep the old attempt separate and explain the uncertainty. If an installed fingerprint is known to belong to another grid, quarantine its association with the intended title. Preserve its attempt separately with an explanation. Install the confirmed grid as a distinct attempt. Do not copy previous entries, notes or completion onto a different grid. Preserve verified good revisions during a timeout or storage failure. Keep manual and automatic jobs deduplicated by puzzle and revision/identity. Pause, retry and airplane-mode cold starts must retain honest availability.

## Native solver acceptance

**Essential player surface.** On a supported puzzle show the board, title, setter, authoritative rules and all clue artwork on first open. A persistent 3×3 number pad below a standard 9×9 grid supports cell-first tap and keyboard entry. Normal Library digits have no stock counts. Provide **Digit**, **Corner**, **Center**, and **Color** modes, explicit erase, undo/redo, a pausable elapsed timer, and **Check**. Tap one cell or use deliberate touch multi-select to apply a mark/color across a selection. A selected mark toggles consistently on repeated use. Givens cannot be replaced. Keep corner and center marks distinct at high zoom. Use a pattern/name as well as a swatch for colors. Preserve rules, text labels, exterior clues and color order when resizing, in dark settings and offline. Keep a reachable cell inspector/linear selector, large controls, keyboard focus and screen-reader labels including mark type. The long/double press shortcuts can follow after these primary paths. [Reference controls](https://sudokupad.app/) · [Reference progress and checking](https://sudokupad.app/script.js?v=0.616.0)

**Three independent checks.** (1) Can native play reproduce all information the solver should see and hide? (2) Which constraints can it actually evaluate? (3) Is there an applicable complete author solution? A faithfully rendered custom-rule board can support progress plus **Manual check**. A complete authorized solution can support **Check finished grid** without claiming each individual custom rule has a validator. Display check scope in words. Never mark an opaque line as a recognized rule based on its paint alone. A missing clue, wrong symbol interpretation or unsupported dynamic reveal invalidates native play, even if the final solution is known. Preserve `null` distinctly from a real digit 0. A saved diagram remains a reference and cannot earn verified completion.

**Fog and custom geometry.** Native support for imported fog requires the exact setter mask, hidden clue layers, symbols, trigger prerequisites and reveal behavior. Imported SudokuPad standard fog can reveal a clipped 3×3 around a correct entry. Authored linked and explicit `cellvalue → foglight` effects can differ. Match the imported puzzle’s rules. Campaign Halo and colony staffing do not substitute for them. Distinguish a 9×9 playable area with extra canvas annotations from a genuinely nonstandard board. If essential annotations, multifield layouts, dynamic scripts, arbitrary symbol alphabets or interactive effects cannot be reproduced, show the reason and the verified player. Broader format support can grow fixture by fixture. [Fog behavior](https://sudokupad.app/feature-fog.js?v=0.616.0) · [Large multi-grid example](https://logic-masters.de/Raetselportal/Raetsel/zeigen.php?chlang=en&id=000T6J)

**Persistence.** Store givens/definition and player attempts separately. Persist entered values, each mark layer, per-cell colors, timer state, undo/redo position, reveal state and check scope against the verified puzzle identity. A confirmed **Restart attempt** resets the attempt without deleting the downloaded puzzle. Migrate existing single-note saves to a documented layer (Corner by default) and preserve their old revision. On a compatible **Play with Colony** challenge, keep a separate attempt and issue its eligible reward once. The authored offline Library and ordinary LMD play remain accessible before starting Colony.

Verify source-only, diagram and native play separately. Compare the givens, outside clues, line order, notes, colors and fog visibility on a supported imported puzzle against the reference player. Normalize string and numeric solution arrays using the declared alphabet.
